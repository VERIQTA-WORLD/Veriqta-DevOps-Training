# 06 AWS

Deploy a small cloud application and explain its access, cost, and recovery.

Build your skills through practical lessons, hands-on labs, portfolio projects, and independent assessments. The curriculum connects technical understanding with verifiable results and troubleshooting practice.

## Your daily curriculum

| Day | Lesson | Observable outcome |
| --- | --- | --- |
| Day 01 | Account safety and budgets | Prepare identity protection and cost notifications with their limits. |
| Day 02 | Identity, roles, and CLI | Verify least-privilege access without storing credentials in the repository. |
| Day 03 | VPCs, subnets, and routing | Map and create the lab request path. |
| Day 04 | Security groups and controlled access | Verify the intended network boundary. |
| Day 05 | EC2 and host access | Launch a small lab host and verify authorized access. |
| Day 06 | Deploy your service | Run and verify the application on the lab host. |
| Day 07 | S3 and data access | Store synthetic artifacts with explicit access controls. |
| Day 08 | Load balancing and health | Verify a healthy request path and a controlled unhealthy target. |
| Day 09 | Database and availability choices | Compare and practice a bounded database connection task. |
| Day 10 | Logs and operational checks | Investigate a failed request from cloud and application evidence. |
| Day 11 | Cloud portfolio and recovery | Demonstrate a deployment and recovery plan. |
| Day 12 | Teardown and independent assessment | Remove billable lab resources and verify what remains. |

Your portfolio connects working artifacts with evidence, explanations, and limitations. Document the decisions you make, the failures you investigate, and the checks that verify your results.
