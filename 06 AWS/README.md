# 06 AWS

Deploy a small cloud application and explain its access, cost, and recovery.

Open the days below in order. Each day will contain its own notes, follow-along lab, portfolio projects, knowledge checks, assessment, troubleshooting, images, and evidence guidance. Day numbers restart within this tool.

## Your daily curriculum

| Day | Lesson | Observable outcome |
| --- | --- | --- |
| Day 01, planned | Account safety and budgets | Prepare identity protection and cost notifications with their limits. |
| Day 02, planned | Identity, roles, and CLI | Verify least-privilege access without storing credentials in the repository. |
| Day 03, planned | VPCs, subnets, and routing | Map and create the lab request path. |
| Day 04, planned | Security groups and controlled access | Verify the intended network boundary. |
| Day 05, planned | EC2 and host access | Launch a small lab host and verify authorized access. |
| Day 06, planned | Deploy your service | Run and verify the application on the lab host. |
| Day 07, planned | S3 and data access | Store synthetic artifacts with explicit access controls. |
| Day 08, planned | Load balancing and health | Verify a healthy request path and a controlled unhealthy target. |
| Day 09, planned | Database and availability choices | Compare and practice a bounded database connection task. |
| Day 10, planned | Logs and operational checks | Investigate a failed request from cloud and application evidence. |
| Day 11, planned | Cloud portfolio and recovery | Demonstrate a deployment and recovery plan. |
| Day 12, planned | Teardown and independent assessment | Remove billable lab resources and verify what remains. |


Planned means the complete lesson has not been published. Only available lessons have links. Do not treat a curriculum outline as a completed class.

Your practical portfolio grows inside these lessons. Each published day's portfolio projects explain what to build, what to verify, what to retain, and what the result demonstrates.
