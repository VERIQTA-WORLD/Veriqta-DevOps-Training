# 20 Security and DevSecOps

Review and harden the complete platform with evidence.

Open the days below in order. Each day will contain its own notes, follow-along lab, portfolio projects, knowledge checks, assessment, troubleshooting, images, and evidence guidance. Day numbers restart within this tool.

## Your daily curriculum

| Day | Lesson | Observable outcome |
| --- | --- | --- |
| Day 01, planned | Threat model and trust boundaries | Map assets, identities, entry points, and credible threats. |
| Day 02, planned | Identity and secrets review | Reduce access and test the effect of a credential rotation. |
| Day 03, planned | Dependency and image findings | Triage vulnerabilities using context and remediation evidence. |
| Day 04, planned | SBOMs, signing, and provenance | Record and verify software origin and composition. |
| Day 05, planned | Policy and hardening | Apply and test a bounded host or workload control. |
| Day 06, planned | Audit evidence and incident response | Investigate a synthetic security event without destroying evidence. |
| Day 07, planned | Backup and disaster recovery | Restore synthetic application data and measure recovery limits. |
| Day 08, planned | Performance, capacity, and cost review | Evaluate a bounded workload and explain platform tradeoffs. |
| Day 09, planned | Final platform portfolio | Deliver architecture decisions, runbooks, release evidence, and incident reports. |
| Day 10, planned | Independent engineering assessment | Defend, operate, troubleshoot, and improve the platform from unfamiliar scenarios. |


Planned means the complete lesson has not been published. Only available lessons have links. Do not treat a curriculum outline as a completed class.

Your practical portfolio grows inside these lessons. Each published day's portfolio projects explain what to build, what to verify, what to retain, and what the result demonstrates.
