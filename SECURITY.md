# Reporting security concerns

Do not publish exposed credentials, private learner information, exploitable details about a real system, or sensitive logs in an issue or pull request.

If GitHub shows a private "Report a vulnerability" option in this repository's Security tab, use it. This option has not been confirmed as enabled. Otherwise, open an issue saying that you need a private reporting channel, without including sensitive details, and wait for the maintainer to provide one. No separate security email or response-time commitment is established here.

If your own credential was exposed, revoke or rotate it through the relevant service immediately. Deleting the visible line does not invalidate the credential or remove copies from Git history. Keep details private while arranging follow-up.

All lab systems should be disposable and use synthetic data. Test only systems you own or are explicitly authorized to use.
