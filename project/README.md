# Your evolving project

You are building a fictional VERIQTA Learning Platform. It uses synthetic courses and learner records, never real customer or business information.

You begin by learning to identify and operate the Linux environment beneath an application. Later, you add a small frontend, Java API, and PostgreSQL database. Application features stay deliberately limited so you can concentrate on delivery and operations.

## Project progression

| Stage | What changes | Evidence you will produce |
| --- | --- | --- |
| Linux foundation | Identify your environment, organize files, then operate a small service. | Baseline, service checks, logs, and an investigation. |
| Networking and collaboration | Trace a request and manage reviewed changes. | Connection diagnosis and Git history. |
| Automation | Replace repeated operational work with Bash and Python. | Explained scripts and meaningful checks. |
| AWS | Deploy a small system with restricted access and cleanup. | Architecture, deployment checks, and cost notes. |
| Build and delivery | Build with Maven, store artifacts, apply quality gates, containerize, and deliver through Jenkins. | Versioned release, pipeline evidence, and rollback. |
| Repeatable infrastructure | Model infrastructure with Terraform and configure hosts with Ansible. | Reviewed plan, drift investigation, and repeatable setup. |
| Kubernetes platform | Deploy locally, package with Helm, then run on EKS. | Workload, traffic, storage, access, and recovery checks. |
| Operations and security | Add Prometheus, Grafana, GitOps, and a final security review. | User-impact dashboards, alerts, incident reports, and restore tests. |

Current stage: Day 001, environment baseline. There is no deployed application yet. Your baseline remains in your private lab directory. Later lessons will add application code here when it is introduced, rather than placing unexplained code ahead of the teaching.

This directory will hold the canonical current project. When an earlier lesson requires a specific version, it will identify the relevant revision or snapshot. Do not maintain several competing copies of the same application.
