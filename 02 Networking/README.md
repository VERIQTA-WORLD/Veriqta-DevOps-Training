# 02 Networking

Trace and diagnose an application request across a network.

Open the days below in order. Each day will contain its own notes, follow-along lab, portfolio projects, knowledge checks, assessment, troubleshooting, images, and evidence guidance. Day numbers restart within this tool.

## Your daily curriculum

| Day | Lesson | Observable outcome |
| --- | --- | --- |
| Day 01, planned | IP addresses, interfaces, and subnets | Map a small lab network and explain local versus remote destinations. |
| Day 02, planned | Routes and gateways | Trace how a packet leaves a host and diagnose a controlled route error. |
| Day 03, planned | Ports, TCP, UDP, and listeners | Match a client connection to a listening application. |
| Day 04, planned | DNS resolution | Investigate a name-resolution failure using observable results. |
| Day 05, planned | HTTP, HTTPS, and TLS | Inspect a request, response, and certificate without treating them as one layer. |
| Day 06, planned | Firewalls and NAT | Explain allowed traffic and diagnose a restricted connection. |
| Day 07, planned | Proxies and load balancing | Follow a request through a small reverse-proxy lab. |
| Day 08, planned | Packet evidence and network incident | Use a bounded capture and deliver a request-path troubleshooting portfolio task. |


Planned means the complete lesson has not been published. Only available lessons have links. Do not treat a curriculum outline as a completed class.

Your practical portfolio grows inside these lessons. Each published day's portfolio projects explain what to build, what to verify, what to retain, and what the result demonstrates.
