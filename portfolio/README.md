# Portfolio milestones

Your portfolio should show what you can build, explain, troubleshoot, and recover. A screenshot by itself does not demonstrate those abilities.

The milestones below are planned. No completed project is claimed by this page.

| Milestone | Demonstration |
| --- | --- |
| Linux service operations | Reproduce a service setup and investigate a controlled failure. |
| Networking investigation | Trace a request and isolate a DNS, routing, port, or application problem. |
| Operational automation | Explain a tested script, its failure handling, and its limits. |
| AWS deployment | Explain identity, networking, access, architecture, cost, and cleanup. |
| Delivery pipeline | Show a tested versioned release and a failed-release recovery. |
| Infrastructure automation | Review a plan, explain state and drift, and rebuild the lab. |
| Kubernetes platform | Demonstrate healthy workloads, traffic, storage, and fault investigation. |
| Observability and GitOps | Connect a reviewed change to deployment health and user-impact signals. |
| Security and recovery | Present a threat review, remediation evidence, and a tested restoration. |

For each finished milestone, retain a short problem statement, architecture, reproducible instructions, redacted evidence, a failure and its diagnosis, tradeoffs, limitations, and cleanup. State what was simulated and what ran on actual infrastructure.

Publish only material you are allowed to share. Keep personal learner records private. Day 001 is a foundation checkpoint, not a claim that you have delivered a production platform.
