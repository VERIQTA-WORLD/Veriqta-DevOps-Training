# Lesson authoring template

This is an authoring checklist, not a published learning day. Replace the planning fields when you create a real lesson. Follow the [teaching standard](../docs/teaching-standard.md).

## Prepare the lesson files

- README.md, with explanation, success criteria, and valid navigation.
- notes.md, with concepts, analogy limits, code explanations, and command reference.
- lab.md, with ordered steps, expected patterns, verification, resumption, and cleanup.
- project.md, with the change to the canonical project and one independent variation.
- knowledge-checks.md, with reasoning and explained answers separated from questions.
- assessment.md, with an independent task and observable pass criteria.
- troubleshooting.md, with evidence, safe actions, and recovery checks.
- evidence/README.md, with required results, redaction, and honest labeling.
- images/, with useful exact diagrams or actual redacted screenshots and text equivalents.
- code/ or manifests/, only when the lesson needs runnable files.

## Review and publish

- Record current official references.
- State precisely what author testing covered and what remains unverified.
- Check links, rendered visuals, syntax, side effects, and cleanup.
- Remove private data and review potential secrets.
- Add the lesson to PROGRESS.md without implying learner completion.
- Preserve existing repository work and publish to the agreed branch.

Do not create an empty lesson directory just because a future day is planned.
