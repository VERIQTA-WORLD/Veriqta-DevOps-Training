# 10 Docker

Run the application as cooperating, inspectable containers.

Open the days below in order. Each day will contain its own notes, follow-along lab, portfolio projects, knowledge checks, assessment, troubleshooting, images, and evidence guidance. Day numbers restart within this tool.

## Your daily curriculum

| Day | Lesson | Observable outcome |
| --- | --- | --- |
| Day 01, planned | Images, containers, and runtimes | Run and inspect a bounded container. |
| Day 02, planned | Your first Dockerfile | Build the application image and verify its behavior. |
| Day 03, planned | Build context, layers, and caching | Explain and improve a repeat build. |
| Day 04, planned | Multi-stage builds and non-root use | Reduce the image contents and verify application access. |
| Day 05, planned | Registries and immutable identity | Publish and retrieve the intended image by recorded identity. |
| Day 06, planned | Networks and service communication | Connect cooperating containers and diagnose a connection error. |
| Day 07, planned | Volumes and persistence | Prove data survives a container replacement. |
| Day 08, planned | Compose application | Run the frontend, API, and database locally. |
| Day 09, planned | Limits, logs, and failure diagnosis | Investigate a controlled application or resource fault. |
| Day 10, planned | Docker portfolio assessment | Deliver a reproducible multi-service lab with recovery and cleanup. |


Planned means the complete lesson has not been published. Only available lessons have links. Do not treat a curriculum outline as a completed class.

Your practical portfolio grows inside these lessons. Each published day's portfolio projects explain what to build, what to verify, what to retain, and what the result demonstrates.
