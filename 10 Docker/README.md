# 10 Docker

Run the application as cooperating, inspectable containers.

Build your skills through practical lessons, hands-on labs, portfolio projects, and independent assessments. The curriculum connects technical understanding with verifiable results and troubleshooting practice.

## Your daily curriculum

| Day | Lesson | Observable outcome |
| --- | --- | --- |
| Day 01 | Images, containers, and runtimes | Run and inspect a bounded container. |
| Day 02 | Your first Dockerfile | Build the application image and verify its behavior. |
| Day 03 | Build context, layers, and caching | Explain and improve a repeat build. |
| Day 04 | Multi-stage builds and non-root use | Reduce the image contents and verify application access. |
| Day 05 | Registries and immutable identity | Publish and retrieve the intended image by recorded identity. |
| Day 06 | Networks and service communication | Connect cooperating containers and diagnose a connection error. |
| Day 07 | Volumes and persistence | Prove data survives a container replacement. |
| Day 08 | Compose application | Run the frontend, API, and database locally. |
| Day 09 | Limits, logs, and failure diagnosis | Investigate a controlled application or resource fault. |
| Day 10 | Docker portfolio assessment | Deliver a reproducible multi-service lab with recovery and cleanup. |

Your portfolio connects working artifacts with evidence, explanations, and limitations. Document the decisions you make, the failures you investigate, and the checks that verify your results.
