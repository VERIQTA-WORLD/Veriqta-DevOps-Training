# Day 02 evidence

Retain actual results privately and publish only reviewed portfolio material. Expected output in the teaching material is a reference pattern, not evidence that you ran a command.

![An evidence chain connects source, operation, comparison, and verified result.](../07%20Images/evidence.svg)

Text equivalent: retain the starting state, the exact operation and its scope, the relevant comparison result, and the final state. Keep private identifiers separate from reviewed public artifacts.

## Guided lab

Keep the verified workspace path, directory inventory including the hidden marker, original and changed configuration values, before-change copy, comparison statuses, restored content, and saved lab-results record. Record any error and the evidence that resolved it.

## Portfolio projects

Keep your workspace README, actual inventory, preserved synthetic configuration, change timeline, comparison results, and working recovery instructions. Verify public file links from the saved portfolio README. State that these are filesystem exercises and that the synthetic configuration is not connected to a running service.

## Practical assessment

Retain a separate attempt directory containing the preserved original configuration, unchanged incoming candidate, final active configuration, repaired operator instructions, evidence record, and the original protected scratch note. Record start and finish times and any interruption. Never turn a skipped check into a passed result.

## Evidence labeling

- Expected example, a pattern supplied by the lesson.
- Observed result, output from your actual command and environment.
- Interpretation, what that observation supports and what it leaves unknown.

Text output is searchable. Screenshots can supplement it, but they must show your real run and must be reviewed before public sharing. Redact private usernames, home prefixes, identifiers, and anything unrelated to the task. Never publish credentials or real customer information.

## Author check boundaries

Author checks exercised the file-operation sequences, overwrite refusal and confirmation, comparison results, restore behavior, protected assessment files, and supplied Markdown templates in an isolated Ubuntu 24.04.3 LTS container running as root. File saving used vi in noninteractive Ex mode. The seven SVG diagrams were rendered. These checks do not certify a regular-user interactive run, timed learner performance, or GitHub browser publication. Verify your own results against the criteria.
