# Linux, Day 02

## Files, paths, and your project workspace

Your application needs more than a running process. It needs files in predictable locations, configuration that you can identify, a recoverable copy before a change, and instructions that work from a stated starting point.

Today you build that foundation. You create a small learning-platform workspace, navigate it, inspect hidden files, copy and rename files, compare contents, and remove only specifically approved disposable files. You then practice a configuration change and restore the earlier file from a verified copy.

## Outcomes

By the end, you can:

- Distinguish absolute paths, relative paths, the current directory, and the parent directory.
- Explain case sensitivity, quoting, and hidden filenames.
- Build and inspect a project directory structure.
- Distinguish creating, copying, moving, renaming, and deleting.
- Verify file content rather than relying on filenames or silent command completion.
- Preserve a before-change copy and verify a file restoration.
- Package your work into a GitHub portfolio with usable instructions and actual evidence.

## Before you begin

Complete Day 01, including saving and reading files with vi. Use the same authorized Linux lab and regular account. These exercises use Bash, GNU Coreutils, GNU Findutils, GNU Diffutils for byte comparison, and vi. No administrator access, installation, cloud resource, or running application is needed.

Allow 60 to 90 minutes for notes and lab, separate sessions for the two portfolio projects, and 45 minutes for the assessment after setup. Take smaller checkpoints when needed. Completion depends on verified results, not on finishing all sections in one sitting.

Use `$HOME/veriqta-devops-labs/linux/day-02/` for private work. It is separate from Day 01. Never run these file-changing commands in a real service directory or a production environment.

## Completion

You can show the intended directory layout, explain where each relative path resolves, preserve source files while copying, verify a backup and a restored file, and complete the independent assessment without changing files outside its scope.
