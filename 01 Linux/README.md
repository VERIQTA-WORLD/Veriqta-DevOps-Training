# 01 Linux

Inspect, operate, troubleshoot, and recover a Linux service.

Open the days below in order. Each day will contain its own notes, follow-along lab, portfolio projects, knowledge checks, assessment, troubleshooting, images, and evidence guidance. Day numbers restart within this tool.

## Your daily curriculum

| Day | Lesson | Observable outcome |
| --- | --- | --- |
| [Day 01](Day%2001/README.md) | Your environment and first baseline | Identify Linux, create your workspace, and save verified observations. |
| Day 02, planned | Files, paths, and your project workspace | Build the learning platform directory structure and safely manage its files. |
| Day 03, planned | Permissions, ownership, and executable files | Set and verify appropriate access to a small script and project files. |
| Day 04, planned | Reading and investigating logs | Answer specific incident questions using a supplied application log. |
| Day 05, planned | Processes and signals | Inspect and stop a controlled process, then complete the first practical checkpoint. |
| Day 06, planned | Users, groups, and least privilege | Separate application access from your personal lab account. |
| Day 07, planned | Packages and software sources | Inspect, install, and remove an approved package in a disposable lab. |
| Day 08, planned | Environment variables and configuration | Supply configuration without confusing shell state with saved files. |
| Day 09, planned | Standard streams, pipes, and exit status | Connect tools, preserve errors, and check whether a command succeeded. |
| Day 10, planned | Text processing for operational questions | Summarize supplied service data using filtering, sorting, and counting. |
| Day 11, planned | Your first local application service | Run a supplied small service and verify a local request and response. |
| Day 12, planned | Service management and startup | Manage the service lifecycle with an environment-appropriate service manager. |
| Day 13, planned | Service logs and failed startup | Diagnose a controlled startup failure from configuration and log evidence. |
| Day 14, planned | CPU, load, and process investigation | Find and explain a controlled CPU workload without guessing from one metric. |
| Day 15, planned | Memory and process limits | Inspect memory pressure and investigate a constrained lab process. |
| Day 16, planned | Filesystems, disk use, and inodes | Distinguish capacity symptoms and locate a controlled file-growth problem. |
| Day 17, planned | Disks and mounts | Inspect storage and practice a safe disposable mount exercise. |
| Day 18, planned | SSH and secure remote access | Verify remote host identity and connect safely to an authorized lab. |
| Day 19, planned | Scheduled tasks and operational timing | Run a small scheduled check and verify its execution and logs. |
| Day 20, planned | Archives, backups, and restoration | Back up synthetic service data and prove that it can be restored. |
| Day 21, planned | Service permissions and hardening | Restrict service access and verify that expected operations still work. |
| Day 22, planned | Linux request-path inspection | Inspect listeners and local reachability before the networking tool section. |
| Day 23, planned | Multi-symptom service incident | Investigate a controlled incident using logs, processes, permissions, and resources. |
| Day 24, planned | Linux portfolio delivery | Package the reproducible service lab, runbook, recovery evidence, and limitations. |
| Day 25, planned | Independent Linux assessment | Operate and recover the service from an unfamiliar but bounded fault. |


Planned means the complete lesson has not been published. Only available lessons have links. Do not treat a curriculum outline as a completed class.

Your practical portfolio grows inside these lessons. Each published day's portfolio projects explain what to build, what to verify, what to retain, and what the result demonstrates.
