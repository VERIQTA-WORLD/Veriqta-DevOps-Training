# 01 Linux

Inspect, operate, troubleshoot, and recover a Linux service.

Build your skills through practical lessons, hands-on labs, portfolio projects, and independent assessments. The curriculum connects technical understanding with verifiable results and troubleshooting practice.

## Your daily curriculum

| Day | Lesson | Observable outcome |
| --- | --- | --- |
| Day 01 | Your environment and first baseline | Identify Linux, create your workspace, and save verified observations. |
| Day 02 | Files, paths, and your project workspace | Build the learning platform directory structure and safely manage its files. |
| Day 03 | Permissions, ownership, and executable files | Set and verify appropriate access to a small script and project files. |
| Day 04 | Reading and investigating logs | Answer specific incident questions using a supplied application log. |
| Day 05 | Processes and signals | Inspect and stop a controlled process, then complete the first practical checkpoint. |
| Day 06 | Users, groups, and least privilege | Separate application access from your personal lab account. |
| Day 07 | Packages and software sources | Inspect, install, and remove an approved package in a disposable lab. |
| Day 08 | Environment variables and configuration | Supply configuration without confusing shell state with saved files. |
| Day 09 | Standard streams, pipes, and exit status | Connect tools, preserve errors, and check whether a command succeeded. |
| Day 10 | Text processing for operational questions | Summarize supplied service data using filtering, sorting, and counting. |
| Day 11 | Your first local application service | Run a supplied small service and verify a local request and response. |
| Day 12 | Service management and startup | Manage the service lifecycle with an environment-appropriate service manager. |
| Day 13 | Service logs and failed startup | Diagnose a controlled startup failure from configuration and log evidence. |
| Day 14 | CPU, load, and process investigation | Find and explain a controlled CPU workload without guessing from one metric. |
| Day 15 | Memory and process limits | Inspect memory pressure and investigate a constrained lab process. |
| Day 16 | Filesystems, disk use, and inodes | Distinguish capacity symptoms and locate a controlled file-growth problem. |
| Day 17 | Disks and mounts | Inspect storage and practice a safe disposable mount exercise. |
| Day 18 | SSH and secure remote access | Verify remote host identity and connect safely to an authorized lab. |
| Day 19 | Scheduled tasks and operational timing | Run a small scheduled check and verify its execution and logs. |
| Day 20 | Archives, backups, and restoration | Back up synthetic service data and prove that it can be restored. |
| Day 21 | Service permissions and hardening | Restrict service access and verify that expected operations still work. |
| Day 22 | Linux request-path inspection | Inspect listeners and local reachability before the networking tool section. |
| Day 23 | Multi-symptom service incident | Investigate a controlled incident using logs, processes, permissions, and resources. |
| Day 24 | Linux portfolio delivery | Package the reproducible service lab, runbook, recovery evidence, and limitations. |
| Day 25 | Independent Linux assessment | Operate and recover the service from an unfamiliar but bounded fault. |

Your portfolio connects working artifacts with evidence, explanations, and limitations. Document the decisions you make, the failures you investigate, and the checks that verify your results.
