# 14 Kubernetes

Deploy, operate, and troubleshoot the multi-tier application.

Open the days below in order. Each day will contain its own notes, follow-along lab, portfolio projects, knowledge checks, assessment, troubleshooting, images, and evidence guidance. Day numbers restart within this tool.

## Your daily curriculum

| Day | Lesson | Observable outcome |
| --- | --- | --- |
| Day 01, planned | Cluster model and local setup | Identify control-plane and workload responsibilities in a local cluster. |
| Day 02, planned | API, manifests, and reconciliation | Apply desired state and inspect the resulting objects. |
| Day 03, planned | Pods and runtime evidence | Inspect a running workload and diagnose a startup failure. |
| Day 04, planned | Deployments and rollout | Change a workload version and verify its rollout. |
| Day 05, planned | Services and discovery | Route requests to healthy application endpoints. |
| Day 06, planned | Configuration and secrets | Provide configuration with explicit secret-handling limits. |
| Day 07, planned | Probes and resource controls | Distinguish startup, readiness, liveness, requests, and limits. |
| Day 08, planned | Storage and persistent data | Verify data through workload replacement. |
| Day 09, planned | Scheduling and placement | Diagnose an unscheduled workload from evidence. |
| Day 10, planned | Traffic entry and TLS | Expose the application through a supported lab traffic-entry option. |
| Day 11, planned | RBAC and workload access | Restrict and test the intended permissions. |
| Day 12, planned | Network policy | Prove permitted and denied application connections. |
| Day 13, planned | Scaling and capacity | Observe a controlled load change and evaluate scaling behavior. |
| Day 14, planned | Upgrade and recovery planning | Explain compatibility, disruption, backups, and recovery boundaries. |
| Day 15, planned | Multi-symptom cluster incident | Diagnose a controlled failure chain without random restarts. |
| Day 16, planned | Kubernetes portfolio assessment | Deliver the application with traffic, storage, monitoring hooks, and recovery evidence. |


Planned means the complete lesson has not been published. Only available lessons have links. Do not treat a curriculum outline as a completed class.

Your practical portfolio grows inside these lessons. Each published day's portfolio projects explain what to build, what to verify, what to retain, and what the result demonstrates.
