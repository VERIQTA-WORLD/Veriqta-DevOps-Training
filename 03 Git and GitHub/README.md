# 03 Git and GitHub

Deliver and recover a reviewed application change.

Open the days below in order. Each day will contain its own notes, follow-along lab, portfolio projects, knowledge checks, assessment, troubleshooting, images, and evidence guidance. Day numbers restart within this tool.

## Your daily curriculum

| Day | Lesson | Observable outcome |
| --- | --- | --- |
| Day 01, planned | Repository and history | Create meaningful commits and inspect the history. |
| Day 02, planned | Branches and changes | Develop an isolated change and compare it with the starting state. |
| Day 03, planned | Remotes and authentication | Push to your authorized repository without exposing credentials. |
| Day 04, planned | Pull requests and review | Propose and explain a focused change. |
| Day 05, planned | Merge conflicts | Resolve a deliberate conflict and verify the result. |
| Day 06, planned | Recovery, tags, and releases | Recover a bad change and identify a reproducible release. |
| Day 07, planned | Collaboration assessment | Deliver a reviewed release with clear history and recovery evidence. |


Planned means the complete lesson has not been published. Only available lessons have links. Do not treat a curriculum outline as a completed class.

Your practical portfolio grows inside these lessons. Each published day's portfolio projects explain what to build, what to verify, what to retain, and what the result demonstrates.
